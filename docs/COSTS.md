请求参数来自 [Chat Completions 文档](https://api-docs.deepseek.com/api/create-chat-completion/)。
开发阶段仅使用 Mock；随后按用户单独授权完成了一次真实推理和官方模型列表确认，结果见
[验收记录](TESTING.md#一次真实-deepseek-调用验收)。没有查询账号余额，供应商实际账单尚未独立核验。

| `deepseek-flash` | $0.30 | $0.006 | $1.20 |

官方所示 Flash 版本为 DeepSeek-V4.1-Flash-1017，Pro 为 DeepSeek-V4-Pro-0813。
规则中的“V4.1 Pro”不是此处可猜造的 API ID，因此默认选用已确认的 `deepseek-v4-pro`，不声称它是未核实的新模型。
始终用高峰费率预留，不假定缓存命中或低谷折扣；官方低谷费率为上述费率的一半。
价格变化时应重新核验 `src/pricing.ts` 的费率和日期，不能只改日期。
价格表超过 30 天，live 调用自动拒绝，Mock 和 dry-run 仍可用但显示价格过期。

## 预计费用（USD）

按实际输入 1000、输出 500 Token，无缓存：Flash 约 **$0.00090/次**，Pro 约 **$0.00330/次**。
Pro 做 10 次约 $0.033；100 次约 $0.33，实际受预算和每日次数限制。
一次正式小额测试可限定输入短文本、`max_output_tokens=128`、`max_cost_usd=0.005`，预算最多预留 $0.005；
以 1000 输入 + 128 输出计算，Pro 约 $0.001827，Flash 约 $0.000454。
字节估算比实际 tokenizer 通常更保守，真正是否能放行要看 dry-run 的 `reserved_cost_usd`。
所有 Mock 推理费用为 **$0**。一次真实实测返回 11 输入、3 输出 Token，按上述高峰价格估算 **$0.0000264**，
低于授权上限 $0.005；这不是供应商账单核验结果。未选云服务商，主机、域名、流量和 IdP 的潜在费用未报价，也未开通。
ChatGPT 订阅费用与 OpenAI API、DeepSeek API 账单相互独立。

## 预算如何执行

当前默认限额为单次 $0.02、UTC 每日 $1、累计 $50、每日最多 200 次；分流及付费默认仍关闭。
本机用户授权的单次上限为 $0.05，其余上限与默认相同；所有窗口共享原账本，不重置历史费用。日预算于北京时间 08:00 换日。

1. JSON 编码 messages 的 UTF-8 字节数 + 128 作为保守输入 Token 估算，并校验输入字节、预计总 Token 与输出上限。
   这不是 DeepSeek 官方 tokenizer；输出通过官方 `max_tokens` 参数限制。thinking 由运营配置决定，推理与最终回答共用输出额度；不发工具/Search/Fetch 请求。
2. 用缓存未命中和高峰单价计算预留金额；检查服务端与调用者单次上限，取更小值。
3. SQLite `BEGIN IMMEDIATE` 事务原子校验 UTC 日预算、累计预算、次数和重复 UUID，再记录 pending 预留，完成后才发 HTTP。
   用纳美元整数记账，避免常见浮点金额累计误差；多个本地数据库连接共享相同预算。
4. 有效 `usage` 返回后，按输入/输出及明确缓存命中量结算，释放未用预留；输出量已涵盖生成用量，不另加一份 reasoning。
   不把官方“余额”或 HTTP 成功等同于精确账单。返回金额是按已核验费率计算的保守估算。
5. 超时、断连、429/5xx、无效用量等任何已派发失败均保留原预留并标为 uncertain；进程中断留下的 pending 也保留。
   不自动退费或重试，不缓存回答；重复 UUID 拒绝，返回原任务的 ledger 状态需操作者检查。
6. 如果上游用量或费用超过预留，记录已报告费用并持久触发 safety halt，拒绝后续推理，等待人工核账。

**费用限制是基于预留估算的应用侧拦截，不是 DeepSeek 账单端的绝对扣费上限。**
远端可能继续处理已取消请求，官方 tokenizer 和费率也可能变化；本服务无法撤销已发生的费用。
正式使用前同时配置供应商侧可用的余额/消费提醒或限额。

账本只保存模式、UUID、UTC 日期、状态和金额，不含文本或 Key。Mock 与 live 各自计账。
跨 UTC 午夜仍在原预留日结算；累计预算覆盖所有日期。原账本的 WAL/SHM 也属于持久状态；备份使用 SQLite backup，
不要在运行中复制单独主文件，更不能通过删库、重建卷或多主机各建一份库来“重置”预算。
只支持单主机本地持久盘；横向扩容需要共享事务数据库或独立中央预算服务，不能直接复用此本地文件方案。

处理 pending/uncertain/halt 时先关闭路由，保留账本备份，对照供应商用量核实。
当前版本没有自动退款或清零工具；只在人工确认后的专门维护变更中调整账目，不能仅因超时将预留清零。
